- FIXED in 1e4825b: T003-B1 `Json.NonFiniteNumbersStayValid`: a NaN/Inf location, game time or FPS is written as `nan`/`inf`, so note.json is invalid JSON (Python `json`, PowerShell `ConvertFrom-Json` and jq reject it; the engine reader accepts it). Fix: NaN/Inf are written as `null`, and WriteNote reports the affected fields as one warning.
- FIXED in 1e4825b: T003-B2 `Failure.PixelCountMismatch`: the note folder is created before the pixels are validated, so a rejected write leaves an empty note folder. SubmitNote then drops the typed note. Fix: inputs are validated before anything is created. A bad or unwritable screenshot is dropped (`"screenshot": ""`, warning) and the note is still saved. Only a failed note.json returns false, and then the folders the call created are removed. On failure SubmitNote logs the text and the full note.json at Warning level.
- FIXED in 1e4825b: T003-B3 `Failure.EmptyRoot`: an empty root resolves against the process dir, and the note was written into `Engine/Binaries/Win64`. Fix: an empty or whitespace-only root is rejected with an error, and nothing is written.
- FIXED in 1e4825b: T003-B4 `Git.MalformedRepoIsUnknown`: non-hash HEAD/ref content (`this is not a commit`, `not-a-hash`, `abc123`) is returned as the commit id instead of "unknown". Fix: only 40 or 64 hex characters (trimmed) are accepted, otherwise "unknown". HEAD refs must be under `refs/`. A broken loose ref no longer falls back to a stale packed id.

### T-004 findings and notes (qa-engineer, 2026-09-22)
- T004-Q1 (minor, open, decision for the lead): after crawling off a ledge the character stays prone for up to 3 frames (50 ms) in the air. The stand-up is blocked while the wider stand capsule still overlaps the ledge corner; it stands up in the air once clear, never penetrates, and goes prone again on landing. `Stance.ProneWalksOffLedge` asserts at most 0.1 s. If "never prone in the air" must be strict, UnProne in the air needs another candidate position (e.g. away from the ledge).
- T004-Q2 (data pipeline, applies to EVERY DataTable): the engine's CSV import turns non-numeric text in a number cell (`fast`, `0.2x`) into 0 and reports NO import problem (`Fallback.NonNumericCellHandled` logs "import problems: 0"). For columns where 0 is valid, a typo becomes a silent 0. DT_Movement is guarded by `Data.NumericCellsAreNumbers`; every other `data/tables/DT_*.csv` (fish, rarity, modifier in T-008) needs the same raw-text check.
- T004-Q3 (info, gap): whether two IDENTICAL hand-built saved moves combine is not deterministic in a headless test world (walk/sprint observed as 0/0 in one run and 1/0 in the next; the moves come from AllocateNewMove outside the real client move pipeline). So bandwidth combining isn't asserted, only reported. `Net.MovesWithDifferentFlagsDoNotCombine` asserts the part that matters for correctness: moves with different sprint/prone/walk wishes never combine. If the playtester sees higher bandwidth or odd corrections while sprinting in 2-player PIE with net emulation, look here first.
- Harness notes for test authors: call `UClass::SetUpRuntimeReplicationData()` before `GetLifetimeReplicatedProps` on a CDO (otherwise RepIndex is unassigned and the engine's duplicate check crashes the whole run). Measure the "camera doesn't move" baseline only after the eye blend has finished (about 40 frames). A capsule stopped by a low edge touches it with its rounded top, so its axis stops inside one radius of the edge.
- Known unrelated failure in lanes: `Project.Playtest.GitCommit` (T003-B5, worktree commondir; being fixed in main).
